1. 先做最简单的文字接龙

看到“我爱猫”，我们先不研究整句话的含义，只把相邻的字两两拿出来：

我→爱→猫

于是记下两条接龙记录：我后面是爱，爱后面是猫。

这种“只看前一个 token，再猜下一个 token”的模型，技术名称叫 Bigram：

P(next token | previous token)
它的记忆只有一个 token。无论前面是“我爱”还是“你爱”，它都只记得最后的“爱”，所以会使用同一套“爱后面接什么”的次数。

2. 给句子插上“开始牌”和“结束牌”

如果只记录普通汉字，程序不知道一句话的第一个字应该怎么选，也不知道什么时候该停。于是我们人为加两张不会显示在最终句子里的牌子：

  • <BOS>：Beginning Of Sequence，句子开始。
  • <EOS>：End Of Sequence，句子结束。

“我爱猫”在统计时变为：

<BOS>→我→爱→猫→<EOS>

生成时先站在 BOS 这张开始牌上，抽到 EOS 这张结束牌时就停。为了让程序能处理它们，BOS 和 EOS 也要像普通字一样拥有 token ID。

3. 做一张“接龙记分表”

我爱猫
我爱狗
你爱猫

展开后：

<BOS> → 我 → 爱 → 猫 → <EOS>
<BOS> → 我 → 爱 → 狗 → <EOS>
<BOS> → 你 → 爱 → 猫 → <EOS>
当前 token下一个 token次数
<BOS>我2
<BOS>你1
我爱2
你爱1
爱猫2
爱狗1
猫<EOS>2
狗<EOS>1

这张表要回答的问题是：“当前是某个 token 时，下一个 token 各出现过几次？”

在代码里，我们用二维列表保存它：

counts[current_id][next_id]

第一个位置表示“现在是哪个 token”，第二个位置表示“接下来是哪个 token”。开始时所有格子都是 0，因为还没读任何句子。每看到一次相邻组合，就把对应格子加 1。

例如，读到“爱猫”：

counts[爱的ID][猫的ID] += 1

4. 把“出现几次”换成“有多大机会”

点击一个当前 token，看看它后面有哪些选择。横条越长，被随机选中的机会越大。

换算方法只是“某个选择的次数除以全部次数”：

某个 next token 的概率 = 对应计数 / 当前行的计数总和
它可能拼出语料里没有的“你爱狗”。原因是它一步一步检查时，开始后出现过“你”，“你”后出现过“爱”，“爱”后出现过“狗”。它不会回头检查完整的“你爱”后面是否真的出现过“狗”。

5. 编程任务

建议文件名：m1/bigram_count.py

只允许使用 Python 自带的功能。不要一次写完整程序，每完成一步就打印结果检查：

  1. 保存三个训练句子。
  2. 收集不重复汉字，加入 <BOS> 和 <EOS>。
  3. 建立两张对照表：token → ID，以及 ID → token。常见变量名才叫 stoi 和 itos。
  4. 创建一张全零的二维记分表：每一行代表“当前 token”，每一列代表“下一个 token”。
  5. 逐句查看相邻 token，每见到一次就把对应格子加 1。
  6. 写一个函数：输入当前 token，把它后面各个选择的次数换成比例。
  7. 先从 BOS 的选择中随机抽一个 token，然后不断接龙；抽到 EOS 就结束。
  8. 生成 10 句。用固定随机种子让结果可以重复，用 max_length 防止错误代码无限循环。

让程序自己帮你核对答案

assert 的意思是：“我认为这个结果必须成立；如果不成立就立刻报错。”请检查：

counts[爱][猫] == 2
counts[爱][狗] == 1
counts[你][爱] == 1
counts[猫][EOS] == 2

P(猫 | 爱) ≈ 2/3
P(狗 | 爱) ≈ 1/3
生成长度不超过 max_length

浮点数可能得到 0.6666666667，因此检查“非常接近 2/3”即可，不要求完全相等。

本课约定：max_length 只计算真正生成的汉字，不包括 BOS 和 EOS；最终返回的句子也不要包含这两个标记。检查 10 个句子时，可以用 all(...) 表示“每一个都符合要求”：

samples = ten_seq(...)
assert all(len(sentence) <= max_length for sentence in samples)
