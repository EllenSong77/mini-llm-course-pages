这一批的学习顺序

第 1 节 · 主线已完成M1D：把计数表变成可训练模型打通 logits → softmax → loss → gradient → update → generation。 M1D 配套交互演示：看 7×7 分数表被梯度改写 第 2 节 · 主线已完成M2A：Tokenizer 到底在决定什么比较字符、词、字节、子词四种切分方法，理解词表大小为什么是设计选择。 第 3 节 · 主线已完成M2B：手工执行 BPE亲眼看见高频相邻片段如何逐轮合并成新 token。 第 4 节 · 当前任务M2C：训练一个工程版中英双语 tokenizer使用 SentencePiece 训练、测试、比较并保存真正可供后续模型使用的 tokenizer。
完成 M2C 后：M2 Tokenizer 结束。接下来先用可检查的小数据把文档变成训练 batch；规模化数据工程在小模型单卡跑通后完善。

下一批五节：课件已准备，等待你完成 M2C

  1. M3A：清洗与去重，再划分训练/验证文档。
  2. M3B：把文档编码成 token，检查 BOS/EOS 与解码结果。
  3. M3C：把不同长度文档组成 batch，逐个位置核对输入和下一 token 答案。
  4. M3D：复用 Bigram 检查 batch 的 loss，理解哪些位置参与评分。
  5. M4A：从 ID 查到 embedding，再用线性映射生成候选分数。

每一步都有代码、实际输出和就地解释。做完后进入单句单头 Attention，再逐步增加因果 mask、batch 和多头。

手搓 300M：总共 7 个阶段

这里按能力里程碑划分，不按周数划分。一共 7 个阶段；阶段 0–1 已完成，你现在处于阶段 2。数据工程会在模型跑通后回访完善。

服务器与实验环境

M0 · 已完成。知道手里的 8×A100 能做什么，验证 CUDA、NCCL、BF16 和数据盘。

语言模型最小闭环

M1 · 主线已完成。理解 next-token prediction，并让最小模型通过梯度下降学习。

Tokenizer 与可训练的小数据

M2–M3 基础部分。把文档转换为可检查的 batch；规模化部分在 M6 后回访。

Transformer 核心

M4–M5。亲手实现 Attention 和完整 Llama-like Decoder，并算清参数量。

单卡训练与性能

M6–M7。训练小模型，理解优化器、精度、显存、吞吐和 checkpoint。

八卡分布式扩展

M8 的 DDP 为主线。M9 的 FSDP/ZeRO 工程根据实测瓶颈选修；理解数据和梯度如何在 8 张 GPU 间流动。

300M Base Model 预训练

M10 + Base 模型评测。冻结架构、数据和预算，完成正式预训练、恢复测试与基础能力评价。

从现在算还剩 5 个阶段。第 6 阶段结束时，你就拥有自己从数据、tokenizer、架构到八卡训练全程构建的约 300M Base Model。

300M 之后还有什么

SFT、DPO、完整评测、KV Cache 和服务化属于后训练与交付扩展（M11–M15）。它们很重要，但不计入“先把 300M Base Model 手搓出来”的 7 个阶段。

这批课程的完成标准

  • 你能解释可训练 Bigram 的参数怎样被 loss 和梯度改变，而不是背 PyTorch API。
  • 你能预测不同 token 切分方案对序列长度和词表的影响。
  • 你能手工解释 BPE 的前三次 merge，并检查代码是否真的做了同一件事。
  • 你能根据中英文、代码、数字、emoji 的测试结果选择 tokenizer，而不是只看“训练成功”。
