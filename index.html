这一批的学习顺序

第 1 节 · 当前任务M1D：把计数表变成可训练模型打通 logits → softmax → loss → gradient → update → generation。 第 2 节M2A：Tokenizer 到底在决定什么比较字符、词、字节、子词四种切分方法，理解词表大小为什么是设计选择。 第 3 节M2B：手工执行 BPE亲眼看见高频相邻片段如何逐轮合并成新 token。 第 4 节M2C：训练一个工程版中英双语 tokenizer使用 SentencePiece 训练、测试、比较并保存真正可供后续模型使用的 tokenizer。
做完以后：M1 全部完成，M2 Tokenizer 全部完成。下一节进入 M3“预训练数据工程”，开始处理真实文档、清洗、去重、切分和数据分片。

手搓 300M：总共 7 个阶段

这里按能力里程碑划分，不按周数划分。包含已经完成的环境阶段，一共 7 个阶段；你现在处于第 1 阶段尾部。

服务器与实验环境

M0 · 已完成。知道手里的 8×A100 能做什么，验证 CUDA、NCCL、BF16 和数据盘。

语言模型最小闭环

M1 · 当前阶段。理解 next-token prediction，并让最小模型真正通过梯度下降学习。

Tokenizer 与预训练数据

M2–M3。把原始中英文文档可靠地转换为可训练 token 流。

Transformer 核心

M4–M5。亲手实现 Attention 和完整 Llama-like Decoder，并算清参数量。

单卡训练与性能

M6–M7。训练小模型，理解优化器、精度、显存、吞吐和 checkpoint。

八卡分布式扩展

M8–M9。从 DDP 到 FSDP/ZeRO，知道数据和梯度如何在 8 张 GPU 间流动。

300M Base Model 预训练

M10 + Base 模型评测。冻结架构、数据和预算，完成正式预训练、恢复测试与基础能力评价。

从现在算还剩 6 个阶段。第 6 阶段结束时，你就拥有自己从数据、tokenizer、架构到八卡训练全程构建的 300M Base Model。

300M 之后还有什么

SFT、DPO、完整评测、KV Cache 和服务化属于后训练与交付扩展（M11–M15）。它们很重要，但不计入“先把 300M Base Model 手搓出来”的 7 个阶段。

这批课程的完成标准

  • 你能解释可训练 Bigram 的参数怎样被 loss 和梯度改变，而不是背 PyTorch API。
  • 你能预测不同 token 切分方案对序列长度和词表的影响。
  • 你能手工解释 BPE 的前三次 merge，并检查代码是否真的做了同一件事。
  • 你能根据中英文、代码、数字、emoji 的测试结果选择 tokenizer，而不是只看“训练成功”。
