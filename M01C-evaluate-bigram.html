训练集与验证集怎样打分为什么用 log代码任务思考题

先说这节到底要解决什么

不能只看生成样本同一个模型每次随机生成的句子可能不同，肉眼很难稳定比较。
要看模型给真实答案的概率有多大真实下一个 token 是“猫”，模型给“猫”的概率越高，这次预测越好。
训练数据和考试数据分开模型用训练集学习，用没有参与学习的验证集检查表现。
最后得到一个平均分把每一步预测的损失加起来，再除以预测次数。

1. 训练集是练习题，验证集是模拟考试

本节使用：

训练集：我爱猫、我爱狗、你爱猫
验证集：你爱狗

计数表只能根据训练集建立。验证集不能拿去增加计数，否则相当于先看了考试答案，再声称考试成绩很好。

验证集可以用来比较模型和选择方案，但不能用来更新当前模型的计数。

2. 每一步只检查真实答案的概率

验证句子“你爱狗”会被拆成：

<BOS> → 你
你 → 爱
爱 → 狗
狗 → <EOS>

当真实答案是“狗”时，模型也许给出了：

猫：2/3
狗：1/3

这一步只取真实答案“狗”的概率，也就是 1/3。真实答案的概率越大，说明模型这一步猜得越好。该给这样的概率打几分？下一节把它换算成损失。

3. 为什么把概率变成负对数

这一步的损失定义如下：

这一步的损失 = -log(模型给真实答案的概率)

先记住下表的大致对应关系，不需要背对数性质：

真实答案概率-log(概率)评价
0.9约 0.11猜得好，损失小
0.5约 0.69一般
0.1约 2.30猜得差，损失大
真实答案概率：0.33损失：1.11

给真实答案的概率偏低，所以损失较大。

使用 log 的重要原因是：一句话包含许多次预测，原本要把许多概率相乘；取 log 后可以改成逐项相加，数值也更容易处理。前面加负号，是为了让“越好越接近 0”。

整个数据集的最终成绩：

平均损失 = 所有步骤的损失之和 / 预测步骤总数
这个指标常叫平均负对数似然，英文缩写 NLL。名字可以以后再记，先理解“真实答案概率越高，平均损失越低”。M1D 会把这套打分接进完整链条：权重 →（softmax）→ 概率 →（取答案·−log）→ loss →（backward）→ 梯度。

4. 代码任务

在 bigram_count.py 的改进版下面继续写。先添加：

import math

实现：

def average_nll(sentences, token_to_id, counts):
    ...

函数按以下步骤工作：

  1. 对每句话加上 BOS 和 EOS。
  2. 逐个取出“当前 token → 真实下一个 token”。
  3. 从计数表中得到真实下一个 token 的概率。
  4. 累加 -math.log(probability)。
  5. 记录一共评价了多少次预测。
  6. 返回“总损失 ÷ 预测次数”。

然后计算并打印：

train_loss = average_nll(s_list, improved_stoi, improved_counts)
validation_sentences = ["你爱狗"]
validation_loss = average_nll(validation_sentences, improved_stoi, improved_counts)

print("训练集平均损失:", train_loss)
print("验证集平均损失:", validation_loss)

测试要求

assert train_loss >= 0
assert validation_loss >= 0
assert train_loss < validation_loss

最后一项在当前固定语料和模型中应该成立。它只是本节语料上的事实，不是普适定律——换一个模型或数据集，训练损失未必仍低于验证损失。

如果真实转移的计数为 0，先让函数返回 float("inf")，表示模型把真实答案判断为不可能。平滑方法后续再学。
