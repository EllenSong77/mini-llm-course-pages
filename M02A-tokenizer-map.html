同一句话，可以切成完全不同的 token

模型只能接收整数。Tokenizer 决定文本先被切成哪些片段，再把每个片段映射成哪个 ID。切法会直接影响序列长度、词表大小、训练成本和模型处理生僻内容的能力。

1. Tokenizer 的工作只有两段

原始文本→切成 token→换成 token ID

例如一种字符切法可能得到：

文本：我爱猫
token：["我", "爱", "猫"]
ID：[104, 28, 376]

104 本身并不天然表示“我”。这是 tokenizer 的词表规定的映射。换一个 tokenizer，同一个“我”可能得到完全不同的 ID。

模型看到的是 ID，但真正参与计算的是 ID 查到的 embedding。ID 只是地址，不是词义大小，也不存在“ID 越近，意思越近”。

2. 四种典型切法

方案“deep learning 深度学习”可能怎样切主要特点
字符 Characterd e e p … 深 度 学 习词表较小，但英文被切得很长。
词 Worddeep / learning / 深度学习常见词很短，但词表会巨大，生词难处理。
字节 Byte按 UTF-8 的原始字节切只有 256 种基本值，任何文本都能表示；中文通常一个字占多个 byte。
子词 Subworddeep / learn / ing / 深度 / 学习常见片段合并，罕见内容拆小；现代 LLM 的常用折中。

实际 tokenizer 还会处理空格、标点、Unicode 规范化和特殊 token，但先抓住核心：常见内容尽量用较大的片段，罕见内容仍能拆开表达。

为什么中文和英文的直觉不同

英文天然有空格，但 unbelievable、代码标识符和新词仍会不断出现。中文通常没有词间空格，“机器学习”该切成“机器/学习”还是“机/器/学/习”需要由规则或数据决定。子词算法就是在这两类语言之间寻找可用折中。

3. vocab_size 不是算出来的唯一答案

vocab_size 是你给 tokenizer 的容量预算：最多想保留多少种 token。训练算法再根据语料决定这些位置放哪些片段。

词表更大

常见词可能用一个 token 表示，序列更短；但 embedding 和输出层更大，低频 token 学得也可能不充分。

词表更小

参数更省，每个 token 出现次数通常更多；但句子会被切得更碎，Attention 要处理更长的序列。

所以 32K、50K、100K 都不是数学上自动得出的答案，而是结合语言、数据规模、模型规模、序列成本和测试结果做出的工程选择。我们的 300M 模型会在真实语料统计之后再冻结词表大小。

词表大小还会影响模型参数：输入 embedding 大致含有 vocab_size × d_model 个参数；若输出层不与它共享权重，还会再有一份相近规模。这个计算到 M5 建完整模型时正式展开。

4. 最小实验：亲眼比较长度

新建 m2/compare_representations.py，使用下面 6 个样本：

samples = [
    "我喜欢机器学习。",
    "Deep learning is useful.",
    "用PyTorch训练300M模型",
    "price = 12.50",
    "def forward(x):",
    "你好👋，LLM!",
]

对每个样本打印三种表示及其长度：

  1. 字符：list(text)。
  2. 空格分词：text.split()。它只是故意设置的简陋 word baseline，不代表合格 tokenizer。
  3. UTF-8 字节：list(text.encode("utf-8"))。
for text in samples:
    characters = ...
    whitespace_words = ...
    utf8_bytes = ...

    print("文本:", text)
    print("字符:", characters, "长度:", len(characters))
    print("空格切词:", whitespace_words, "长度:", len(whitespace_words))
    print("UTF-8 字节:", utf8_bytes, "长度:", len(utf8_bytes))

你要观察的不是哪种“必赢”

  • 中文在 split() 下为什么可能整句只有 1 个片段？
  • 中文字符在 UTF-8 下为什么通常比英文 ASCII 字符占更多 byte？
  • 代码、数字、emoji 会让“按词切”遇到哪些边界问题？

这一节不要求你自己写 Unicode 解析器，也不要求记编码知识。能根据输出说明各种切法的代价就够了。
