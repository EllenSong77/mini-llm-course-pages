语料三轮合并学到了什么代码验收

先看 BPE 的全部核心

把词拆小→统计所有相邻对→找出现最多的一对→全局合并→重复

这里的 BPE 是 Byte Pair Encoding 的名字，但为了先看清算法，我们从中文字符开始，而不是直接处理原始 byte。工程版会交给 SentencePiece。

1. 一份带出现次数的小语料

机器学习 × 3
机器视觉 × 2
深度学习 × 1

初始时，每句话都按字符拆开：

[机, 器, 学, 习] × 3
[机, 器, 视, 觉] × 2
[深, 度, 学, 习] × 1

“×3”非常重要：它表示这句话在语料里出现 3 次，所以其中每个相邻对都要贡献 3 次计数。

相邻 token 对总次数次数从哪里来
机 + 器5机器学习 3 次 + 机器视觉 2 次
学 + 习4机器学习 3 次 + 深度学习 1 次
器 + 学3机器学习 3 次
器 + 视2机器视觉 2 次
视 + 觉2机器视觉 2 次
深 + 度1深度学习 1 次
度 + 学1深度学习 1 次

2. 手工执行前三轮

第 1 轮：合并“机 + 器”

它出现 5 次，是当前冠军。把语料中的相邻 机, 器 全部替换成一个新 token 机器：

[机器, 学, 习] × 3
[机器, 视, 觉] × 2
[深, 度, 学, 习] × 1

第 2 轮：重新统计，再合并“学 + 习”

每次合并后必须重新统计，因为 token 边界已经变了。现在 学 + 习 出现 4 次：

[机器, 学习] × 3
[机器, 视, 觉] × 2
[深, 度, 学习] × 1

第 3 轮：合并“机器 + 学习”

现在它出现 3 次：

[机器学习] × 3
[机器, 视, 觉] × 2
[深, 度, 学习] × 1
新 token 不一定是语言学意义上的完整“词”。BPE 只根据训练语料中的频率做合并；数据不同，学到的 merge 顺序也不同。

3. 每次 merge 实际改变了什么

词表多一个 token

例如合并后新增 机器，原来的 机 和 器 通常仍保留，用于表示其他内容。

常见文本少一个位置

[机, 器] 变成 [机器]，以后序列更短。

模型承担更大的词表

每增加一种 token，embedding/输出层就多一行相关参数。

merge 顺序必须保存

编码新文本时要重放同一套规则，不能临时重新猜。

BPE 的核心取舍正是：花更大的词表，换取常见文本更短的 token 序列。

def train_bpe(corpus, num_merges):
    working = [(tokens.copy(), frequency) for tokens, frequency in corpus]
    merge_rules = []

    for round_id in range(num_merges):
        pair_counts = count_pairs(working)
        if not pair_counts:
            break

        # sorted 让“次数相同”的情况也能稳定得到同一结果
        best_pair = max(sorted(pair_counts), key=pair_counts.get)
        merge_rules.append(best_pair)
        working = [
            (merge_tokens(tokens, best_pair), frequency)
            for tokens, frequency in working
        ]
        print(round_id + 1, best_pair, pair_counts[best_pair], working)

    return working, merge_rules


final_corpus, rules = train_bpe(corpus, num_merges=3)
assert rules == [("机", "器"), ("学", "习"), ("机器", "学习")]
assert final_corpus[0][0] == ["机器学习"]
这里只验证 BPE 最重要的三件事：频率加权统计、选出最高频相邻对、合并后重新统计。生产级的 Unicode、特殊 token、并发、文件格式和解码交给成熟库。

5. 一个故障实验

故意把 counts[(left, right)] += frequency 改成每次只加 1，再运行三轮。

观察 merge 顺序是否变化，并解释：如果忽略每句话的出现频率，算法实际回答的就不再是“整份训练语料中哪一对最常见”，而是“这一对出现在多少种不同句子里”。
